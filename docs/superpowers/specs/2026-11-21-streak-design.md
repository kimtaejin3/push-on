# 스트릭(연속 운동 일수) 설계

날짜: 2026-11-21 · 상태: 승인됨

## 1. 배경과 목표

사용자는 사람들이 **하루도 빼먹지 않고** 운동하길 원하고, 듀오링고처럼 **매일 앱에 다시 오게
강하게 묶는** 장치를 원한다. 매일 운동 전환(`2026-11-21-daily-program-design.md`)이 "매일 할 것"을
준다면, 스트릭은 "오늘 안 하면 잃는 것"을 만든다.

듀오링고 스트릭이 사람을 붙잡는 요소는 네 가지다. 이 설계는 넷을 모두 넣는다.

1. **항상 보이는 숫자** — 앱을 열 때마다 내 연속 일수가 보인다
2. **이어갔을 때의 보상** — 그날 첫 운동을 끝내면 축하 화면이 뜬다
3. **잃기 직전의 알림** — 오늘 안 하면 사라진다는 걸 저녁에 알려준다
4. **한 번의 실수는 봐주는 장치** — 하루 빠졌다고 긴 스트릭이 0 이 되면 그대로 그만두기 쉽다

### 성공 기준
- 홈을 열면 현재 스트릭과 오늘 했는지가 바로 보인다
- 그날 첫 운동을 마치고 결과 화면을 떠날 때 축하 화면이 하루 한 번 뜬다
- 오늘 아직 안 했고 지킬 스트릭이 있으면 저녁에 알림이 온다
- 하루 빠져도 보호권이 있으면 스트릭이 유지되고, 그 사실을 알려준다
- 스트릭 숫자는 어느 기기에서 봐도 같다 (운동 기록에서 계산)

### 범위 밖
리더보드에 스트릭 표시, 친구·공유, 끊긴 스트릭 복구(유료/광고), 홈 화면 위젯, 앱 아이콘 배지,
서버 푸시 알림(로컬 알림만 쓴다), 스트릭 보호권을 직접 사고 쓰는 화면.

### 이렇게 되면 실패 (anti-goals)
- 숫자가 틀린다 (했는데 안 올라가거나, 기기마다 다르다)
- 운동 중이나 휴식 중에 축하 화면이 끼어든다
- 그만둔 사람에게 알림이 끝없이 온다
- 끊겼을 때 문구가 꾸짖는다 — 끊긴 사실 + 최고 기록 + "오늘 다시 시작"만 말한다
- 스트릭 정보를 못 불러왔다고 운동 흐름이 막힌다

## 2. 접근 방식

갈리는 지점은 "스트릭을 어디서 계산하고 어디에 두느냐"다.

| 방법 | 장점 | 단점 |
|---|---|---|
| **A. 운동한 날짜 목록을 서버에서 받아 앱이 계산 (채택)** | 숫자가 운동 기록 그 자체에서 나와 틀릴 수 없고 기기 간 동일. 기존 사용자도 바로 지금까지의 스트릭이 보임. 규칙이 순수 함수라 테스트 가능 | 날짜 목록을 주는 SQL 함수 1개를 Supabase 에 추가해야 함 (수동 실행) |
| B. 서버에 스트릭 테이블을 두고 저장할 때마다 갱신 | 조회가 가벼움 | 테이블·갱신 로직 추가, 저장 실패·중복 시 숫자가 어긋날 수 있음 |
| C. 폰에만 저장 | 서버 작업 없음 | 재설치·기기 변경 시 스트릭이 사라짐 — 스트릭에서 가장 나쁜 실패 |

A 를 택한 이유: 스트릭은 숫자가 틀리거나 사라지면 오히려 그만두는 계기가 된다. (작성자 판단)

날짜 목록은 기존 `pushup_sets.workout_date`(운동 저장 시 기기 날짜로 기록되는 YYYY-MM-DD)에서
나온다. 세트 단위 행을 앱이 전부 받아 오는 대신, 본인의 **운동한 날짜만 중복 없이** 돌려주는
SQL 함수를 하나 둔다. 이 함수가 없거나 실패하면 스트릭 관련 화면·알림은 모두 숨긴다(운동은 정상).

## 3. 스트릭 규칙

### 3.1 하루의 기준 (작성자 판단)
- 그날 푸쉬업을 **1개 이상 기록**하면 그날은 "한 날"이다. 모드는 가리지 않는다
  (챌린지 · 세트 · 100개 챌린지 · 테스트). 100개 챌린지에서 세트를 못 채워 실패한 날도 한 날이다 —
  스트릭은 "나왔는가"를 세고, 진도는 프로그램이 따로 센다.
- 날짜는 운동을 저장한 기기의 날짜(`workout_date`)를 그대로 쓴다. 자정에 날이 바뀐다.

### 3.2 계산
운동한 날짜 목록과 오늘 날짜만으로 계산한다. 첫 운동일부터 **어제까지** 하루씩 따라가며:

- 한 날: 스트릭 +1. 최고 기록 갱신. 스트릭이 7의 배수가 됐고 보호권이 2개 미만이면 보호권 +1.
- 안 한 날: 스트릭이 1 이상이고 보호권이 있으면 보호권 −1 하고 그날을 "보호된 날"로 표시
  (스트릭 숫자는 그대로). 보호권이 없으면 스트릭 0.

그다음 오늘:
- 오늘 했으면 스트릭 +1 (위와 같은 보호권 규칙), "오늘 완료".
- 오늘 아직 안 했으면 스트릭은 그대로이고, 1 이상이면 "오늘 안 하면 끊기거나 보호권을 쓰게 되는" 상태다.

결과로 나오는 것: 현재 스트릭, 오늘 완료 여부, 최고 기록, 보유 보호권(0~2), 이번 주(월~일) 각 날의
상태(함 / 보호됨 / 안 함 / 아직 안 온 날), 방금 끊겼는지(어제 0 이 됐고 그 전 스트릭이 얼마였는지).

### 3.3 스트릭 보호권 (작성자 판단)
- 7일 이어갈 때마다 1개, 최대 2개까지 쌓인다. 하루 빠지면 자동으로 1개 쓰인다.
- 따라서 이틀 연속 빠져도(2개 보유 시) 스트릭이 유지되고, 사흘째에 끊긴다.
- 보호권도 날짜 목록에서 계산되므로 따로 저장하지 않는다.
- 사용자가 직접 켜고 끄거나 사는 기능은 없다.

### 3.4 마일스톤
3 · 7 · 14 · 30 · 50 · 100 · 200 · 365일.

### 3.5 저장에 실패한 운동 (작성자 판단)
스트릭은 저장된 운동 기록에서 나오는데, 지금은 운동 저장이 실패하면 그 기록이 그냥 사라진다
(챌린지는 로그만 남기고 홈으로, 세트는 경고만, 테스트는 한 번 시도 후 무시). 그대로 두면
네트워크가 잠깐 끊긴 날 스트릭 하루를 잃는다 — 이 설계가 가장 피하려는 실패다. 그래서:

- 저장에 실패한 운동은 **폰에 보관했다가 다시 보낸다** (앱을 열 때, 앱으로 돌아올 때, 다른
  저장이 성공했을 때). 원래 운동한 날짜·시각 그대로 보낸다.
- 보관 중인 운동도 스트릭 계산에서는 **한 것으로 친다** (오늘 완료, 축하 화면, 알림 취소 모두).
- 다시 보내다가 같은 운동이 두 번 기록되면 안 된다 (첫 시도가 실제로는 성공했던 경우 포함).
- 대상은 챌린지·세트·프로그램·테스트의 모든 운동 저장이다.

## 4. 화면

문구는 예시다. 들어가야 하는 정보는 그대로, 표현은 만드는 사람이 기존 톤에 맞춘다.

### 4.1 홈
오른쪽 위에 불꽃과 숫자. 오늘 했으면 켜진 색, 아직이면 흐린 색. 누르면 스트릭 화면.
제목 아래 한 줄 배너가 상황을 말한다.

```
PushOn                                        🔥 12
오늘 운동하면 13일째예요
```

| 상황 | 배너 |
|---|---|
| 오늘 완료 | "13일 연속! 내일도 이어가요" |
| 오늘 아직, 스트릭 1 이상, 18시 전 | "오늘 운동하면 13일째예요" |
| 오늘 아직, 18시 이후, 보호권 없음 | "오늘이 지나면 12일 스트릭이 사라져요" |
| 오늘 아직, 18시 이후, 보호권 있음 | "오늘 안 하면 보호권을 써요 (남은 보호권 1개)" |
| 어제 보호권이 쓰였고 오늘 아직 | "어제는 보호권이 12일 스트릭을 지켜줬어요. 오늘은 직접 이어가요" |
| 방금 끊김(어제 0 이 됨), 오늘 아직 | "12일 스트릭이 끊겼어요. 최고 기록 12일 · 오늘 다시 시작해요" |
| 운동 기록이 한 번도 없음 | "오늘 첫 운동으로 스트릭을 시작해요" |

### 4.2 축하 화면
그날 **첫 운동을 마치고 결과 화면을 떠날 때** 한 번 뜬다 (챌린지 결과, 세트 요약, 프로그램 요약,
테스트 결과 모두). 운동 중·휴식 중에는 절대 뜨지 않는다. "계속"을 누르면 원래 가려던 곳으로 간다.

```
            🔥
        13일 연속

   월  화  수  목  금  토  일
   ✓   ✓   ✓   ❄   ✓   ✓   ●

        내일도 이어가요
          [ 계속 ]
```

- 마일스톤 날: "7일 달성!" 처럼 강조하고, 보호권을 받았으면 "스트릭 보호권 1개를 받았어요.
  하루 빠져도 스트릭을 지켜줘요"를 덧붙인다.
- 끊긴 뒤 다시 시작한 날: "다시 1일째! 최고 기록 12일에 도전해요".
- 알림을 아직 허용하지 않았으면 첫 축하 화면에 "스트릭 알림 받기" 버튼을 둔다 (누르면 권한 요청).
  거절하면 다시 조르지 않고, 스트릭 화면에서 켤 수 있다.
- 스트릭 정보를 못 불러왔으면 축하 화면을 건너뛰고 바로 이동한다.
- 광고가 도입되면(별도 계획) 순서는 축하 화면 → 광고.

### 4.3 스트릭 화면 (홈의 불꽃을 누르면)
- 큰 숫자와 "N일 연속"
- 이번 주 7칸 (함 ✓ / 보호됨 ❄ / 안 함 / 오늘)
- 최고 기록
- 스트릭 보호권 보유 수(0~2)와 설명: "7일 이어갈 때마다 1개, 하루 빠지면 자동으로 써요"
- 다음 마일스톤까지 남은 일수
- 스트릭 알림 켜기/끄기와 알림 시각

## 5. 알림

기존 운동 알림과 같은 로컬 알림(notifee)을 쓴다. 서버는 관여하지 않는다.

- **저녁 알림** (기본 21:00, 스트릭 화면에서 변경): 오늘 아직 안 했고 스트릭이 1 이상일 때.
  "🔥 12일 스트릭이 오늘 끝나요. 푸쉬업 1개만 해도 이어져요" / 보호권이 있으면 "오늘 안 하면 보호권을 써요".
- **마지막 알림** (22:30 고정): 스트릭이 3 이상이고 그때까지도 안 했을 때. "자정까지 남았어요. 12일을 지켜요".
- 오늘 운동을 하면 오늘 치 알림은 취소된다.
- **앱을 안 여는 동안**: 앱을 열거나 운동을 저장할 때마다, 그 뒤로 계속 안 한다고 가정하고
  **앞으로 3일 치**를 미리 걸어 둔다. 날마다 그 시점의 상태에 맞는 문구가 간다
  (스트릭 위험 → "어제는 보호권이 지켜줬어요" → "스트릭이 끊겼어요. 오늘 다시 시작해요").
  3일이 지나면 더 보내지 않는다.
- 알림 문구를 정하는 것도 날짜 목록·현재 시각·알림 시각만으로 계산하는 순수 함수로 둔다.
- 권한은 축하 화면이나 스트릭 화면에서 사용자가 켤 때만 요청한다. 기본은 꺼짐.
- 100개 챌린지의 운동 알림과는 독립이다. 둘 다 켜면 둘 다 온다 (합치지 않는다).

## 6. 제약
- **SQL 함수 1개 추가** (사용자가 Supabase SQL Editor 에서 수동 실행, 레포에 `STREAK.sql` 로 둔다):
  로그인한 본인의 `pushup_sets.workout_date` 를 중복 없이 돌려준다. 호출자 권한으로 실행해
  기존 RLS 를 그대로 따른다. 날짜가 많아져도 잘리지 않게 한 번에(배열로) 돌려준다.
  함수가 없으면 앱은 스트릭을 숨길 뿐 다른 동작은 그대로다 → 앱을 먼저 배포해도 안전하다.
- 테이블·컬럼은 추가하지 않는다. 구버전 앱에는 영향이 없다.
- 알림 설정(켜짐·시각)과 "오늘 축하 화면을 봤는지"는 폰에 저장한다 (AsyncStorage).
- 계산 규칙과 알림 계획은 순수 함수로 두고 `__tests__/domain` 에서 검증한다. 화면은 자동 테스트가 없다.
- 운동 저장 직후 스트릭이 바로 갱신돼야 한다 (기존 운동 기록 캐시 무효화에 함께 묶는다).
- 보관 중인 운동(3.5)은 폰에 저장한다. 로그아웃하거나 다른 계정으로 로그인하면 남의 계정으로
  보내지 않는다.

## 7. 만드는 사람에게 맡기는 것
- 불꽃·눈꽃 아이콘(이모지 vs 아이콘 폰트), 색, 축하 화면의 움직임
- 축하 화면을 별도 화면으로 둘지 모달로 둘지
- 문구의 최종 표현
- SQL 함수 이름과 반환 형태의 세부
- 보관한 운동을 다시 보낼 때 중복을 막는 방법
