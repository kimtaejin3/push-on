# 리디자인 5단계 설계 — 광고 배치와 동의

날짜: 2026-11-21 · 상태: 승인됨

## 1. 배경과 목표

에드몹 기반(노출 규칙·원격 설정·SDK·`useAds`·`AdBanner`)은 이미 들어가 있고 광고는 꺼져 있다
(`docs/superpowers/plans/2026-10-19-ads.md` Task 1~4). 화면 배치(Task 5)는 리디자인 뒤로 미뤄 뒀다.
리디자인 디자인 파일은 10월 광고 설계(`2026-10-09-ads-design.md`)와 다른 광고 정책을 그렸고,
사용자는 **디자인의 정책(A안)** 을 골랐다. 이 문서는 10월 설계의 배치·빈도·동의 부분을 대체한다.

사용자가 정한 것:
- **배치·빈도는 디자인대로**: 운동 밖 화면 4곳에 화면당 광고 1개, 전면은 결과 뒤 하루 1회. 하단 고정 배너 없음.
- **동영상 광고 허용**: 전면은 이미지·동영상 모두, 네이티브도 이미지·동영상 모두(소리 없이 시작).
- **iOS 추적 동의(ATT) 넣기**: 첫 운동 결과 뒤 사전 안내 → 시스템 창.

### 성공 기준
- 운동 중(준비·카운트·휴식)·테스트·로그인·설정·프로필·100개 달성 화면에는 광고가 한 번도 나오지 않는다
- 홈·결과·기록·리더보드에 화면당 광고 1개, 자리 확보(스켈레톤) 후 실패하면 자리를 접는다
- 전면은 결과 [확인] 뒤 "저장 중" 다음에만, 하루 1회·12시간 간격, 면제 조건이면 나오지 않는다
- 동의 흐름(ATT·UMP)이 끝나기 전에는 광고 요청이 하나도 없다
- 서버 설정 하나로 광고 전체·전면만 즉시 끌 수 있다(기존 구조)

### 범위 밖 (6단계)
광고 제거 결제(₩5,900)와 "광고 없이 쓰기" 링크·스낵바의 결제 안내, 보상형 광고(스트릭 보호권),
앱 오픈 광고. 이 문서에서 해당 자리는 그리지 않는다.

### 이렇게 되면 실패 (anti-goals)
- 광고 때문에 운동이 시작되거나 끝나는 흐름이 막히거나 늦어진다
- 광고가 버튼·탭바에 붙어 실수로 눌린다(에드몹 정책 위반)
- 광고가 앱 콘텐츠처럼 보인다(위장)
- 동의 전·광고 꺼짐 상태에서 SDK 가 광고를 요청한다

## 2. 접근 방식

| 방법 | 판단 |
|---|---|
| **A. 디자인 정책: 네이티브(홈·결과·리더보드) + 인라인 배너(기록) + 결과 뒤 전면 (채택)** | 광고 수가 적고 정책 위험이 낮다. 이미 만든 새 화면 틀(광고 자리 시안 BVAkZ·hzROn·KrjtX·M3R5u)에 맞는다 |
| B. 10월 설계: 홈·기록 하단 고정 배너 + 전면 하루 2회 | 만들기 쉽고 노출이 많지만 탭바 옆 고정 배너는 실수 클릭 정책 위험 |

사용자가 A 를 골랐다.

## 3. 배치

디자인: 배치 지도 `K1pFwS`, 부품 `miaaz`(Ad/Native Medium, Ad/Inline Banner, Ad/Skeleton), 화면별 시안,
상태 `rnkiX`(AD-04·15). 전달 묶음 `.superpowers/design-handoff/redesign/`.

| 화면 | 형식 | 위치 | 시안 |
|---|---|---|---|
| 홈 | 네이티브(중간 크기) | '다른 운동' 아래, 탭바와 40 이상 떨어짐 | `BVAkZ` (보상형 입구는 6단계라 그리지 않음) |
| 결과(네 결과 화면 모두: 자유 세트·100개 챌린지 운동·한 번에 몇 개?·100개 챌린지 테스트) | 네이티브 | '다음 운동'(없으면 사실 행) 아래, [확인]과 44 이상 | `hzROn` ("광고 없이 쓰기" 링크는 6단계) |
| 기록 | 인라인 적응형 배너, 높이 110 고정 | 달력과 주간 총합 사이, 위아래 28 | `KrjtX` |
| 리더보드 | 네이티브 | 10위 다음, 그 뒤 11위부터 | `M3R5u` |

- 광고 없는 곳: 운동(준비·카운트·휴식·일시정지), 한 번에 몇 개?·100개 챌린지 테스트의 **카운트 화면**, 100개 챌린지 탭,
  100개 달성, 스트릭, 설정·계정·프로필·문서, 로그인, 자유 세트 설정.
- 표시 규칙(디자인 정책 03·04): '광고' 표시 15px 이상, AdChoices, 중립 CTA, 앱 행과 다른 면(`ad-*` 토큰),
  버튼·탭바 옆 금지, 로드 전 같은 높이 스켈레톤, 실패하면 자리를 접는다(AD-15 의 화면별 간격).
- 네이티브 동영상은 소리 없이 시작한다.

## 4. 전면 흐름

`puDBa`, AD-04.

1. 결과 화면에서 **지금 `celebrateThen` 을 거쳐 나가는 모든 출구**([확인]·[프로그램으로]·[이 레벨로 한 번 더]·하향 성공 뒤 이동·
   [기록에서 보기]) → **스트릭 축하**(오늘 첫 운동이면, 지금처럼) →
   **"저장 중" 화면**(B1: "오늘 기록 저장 중 · N개 · N주차 Day D", 0.5~1초, 그동안 전면을 불러온다) →
   **전면**(나올 조건일 때만) → **지금의 목적지**(프로그램 결과 → 100개 챌린지 탭, 그 밖 → 홈).
   - 디자인은 끝이 홈인데, 목적지는 지금 앱 기준을 지킨다(원칙 A). (작성자 판단)
   - 축하 → 광고 순서는 스트릭 스펙 4.2 그대로.
2. 목적지 도착 뒤 1회 스낵바(토스트): "N개 저장했어요 · 기록에서 볼 수 있어요 [보기]" — 전면이 나왔든 아니든.
   목적지가 기록 탭이면 띄우지 않는다. 결제 안내 문구는 6단계.
   - 지금 축하를 거치지 않는 출구(반영 못 함·대기 화면, 저장 실패 뒤 이동, 0개 결과)는 광고 흐름도 거치지 않는다. (작성자 판단)
3. "저장 중" 화면은 전면이 면제여도 거친다(짧게, 0.5초). 저장이 보관(오프라인)으로 끝났으면 "저장 대기"로 표시.
   (작성자 판단 — 흐름을 매번 같게)

### 빈도와 면제
- 하루 1회, 최소 12시간 간격, 첫 3회 운동 면제 → 서버 설정 기본값을 `interstitial_daily_cap 1`,
  `interstitial_min_gap_seconds 43200`, `interstitial_grace_workouts 3` 으로 바꾼다(`APP_CONFIG.sql`, 아직 미실행).
- 면제 조건(디자인 AD-04): 오늘 이미 봄, 첫 3회 운동, **테스트한 날**, **100개 달성일**, 전면 로드 실패.
  - 테스트 = 100개 챌린지 테스트와 "한 번에 몇 개?"(둘 다 최대 개수 측정, 디자인 O-04). 그날 테스트를 한 번이라도
    했으면 그날은 전면이 없다. (작성자 판단)
  - 100개 달성일 = 최종 테스트로 프로그램을 완료한 날.
  - 보상형을 본 세션·광고 제거 구매자는 6단계에서 더한다.
- 에드몹 콘솔에서도 전면 광고 단위에 빈도 상한(1회/12시간)을 건다(앱 판정과 이중으로).

## 5. 동의 (ATT·UMP)

`HWhD8`(AD-12·13), 설정 SE-08·SE-14.

- 첫 실행에는 카메라 권한만 묻는다(지금과 같음). **첫 운동 결과 화면(네 결과 화면 중 어느 것이든)을 떠날 때 한 번**
  동의 흐름을 돈다. Android 도 같은 시점이다 — 한국에서는 보이는 화면 없이 UMP 확인만 하고 끝나지만, 플랫폼마다
  다르게 두지 않는다. 그래서 운동을 한 번도 끝내지 않은 사용자에게는 어디에도 광고가 나오지 않는다(리텐션 우선). (작성자 판단)
  순서:
  iOS → AD-12 사전 안내("광고를 덜 귀찮게 보여 드리려고 물어볼게요… 허용하지 않아도 앱은 똑같이 써요" [계속],
  닫기 없음) → 시스템 ATT 창. 그다음 UMP(EEA·영국 등 필요한 지역에서만 동의 양식).
  - 순서: 결과 [확인] → 축하 → (첫 결과일 때만) 동의 흐름 → 저장 중 → 목적지. 첫 결과는 첫 3회 면제라 전면이 없다.
- **동의 흐름이 끝나기 전에는 SDK 를 초기화하지 않고 광고를 요청하지 않는다.** 지금 조건(서버 설정이 광고 켜짐)에
  "동의 흐름 완료"를 더한다. 이미 결과를 본 기존 사용자(업데이트로 처음 들어온 경우)는 다음 결과 화면에서 한 번 돈다.
- 광고가 꺼져 있으면(서버 설정) 동의 흐름도 돌지 않는다 — 켜진 뒤 첫 결과에서. (작성자 판단 — 광고가 없는데 묻지 않게)
- 맞춤 광고: iOS 는 ATT 허용이면 맞춤, 아니면 비맞춤만. Android·그 밖은 UMP 결과를 따른다.
  지금의 `requestNonPersonalizedAdsOnly: true` 고정은 이 규칙으로 바뀐다.
- iOS `Info.plist` 에 `NSUserTrackingUsageDescription`(한국어, 사전 안내와 같은 취지).
- 설정 "광고와 개인정보" 섹션(SE-08·14): 맞춤 광고 동의 변경(UMP 개인정보 옵션이 필요한 지역에서만 보임),
  앱 추적 허용 상태(iOS — 허용 안 함/허용/아직 안 물어봄, 누르면 시스템 설정 또는 AD-12), 광고 신고 방법(시트),
  안내 문구 "운동 기록·카메라 영상·건강 데이터는 광고에 쓰지 않아요. 운동 중에는 광고가 나오지 않아요."
  광고가 꺼져 있으면 섹션 전체를 숨긴다. (작성자 판단)

## 6. 광고 단위

- 새로 만든다(에드몹 콘솔, 작성자가 **구현 시작 전에** 만들고 ID 를 계획에 적는다): 네이티브 고급 — 홈·결과·리더보드 ×
  Android·iOS = 6개(배치별 수익을 따로 보려고). 이미지·동영상 허용. (작성자 판단)
- 기존 사용: 전면(Android·iOS — 동영상 허용 확인, 빈도 상한 설정), 배너(기록 인라인).
- `__DEV__` 에서는 테스트 ID.

## 7. 지난 검토에서 넘어온 것 (이번에 고친다)
- 전면을 불러오는 도중 서버에서 광고를 끄면 그 한 번은 뜰 수 있다 → 보여주기 직전에 설정을 다시 확인한다.
- 전면이 실제로 열렸는데 "열림" 신호가 5초보다 늦으면 다음 호출 잠금이 먼저 풀린다 → 잠금은 닫힘·오류·전체 상한까지 유지.

## 8. 제약
- 기존 동작(결과 판정·저장·보관·축하·목적지·뒤로가기 가드)은 그대로. 광고 실패·지연이 이동을 막지 않는다.
- `react-native-google-mobile-ads` 16.0.1 고정(RN 0.79 codegen 제약). 네이티브 광고·UMP·ATT 를 이 버전의 공식 API 로.
  ATT 요청이 이 라이브러리에 없으면 `react-native-tracking-transparency` 등 New Architecture 지원 라이브러리를 공식 문서로 확인해 추가.
- DB 변경은 `APP_CONFIG.sql` 기본값 수정뿐(테이블은 아직 만들어지지 않았다). 사용자가 출시 뒤 실행한다.
- 광고를 켜기 전까지 앱 동작은 지금과 같아야 한다(광고 자리도 그리지 않음 — 서버 설정이 꺼져 있으면 스켈레톤도 없음).
- 검증: jest·tsc·eslint, iOS·Android 빌드, 기기에서 `__DEV__` 테스트 광고로 확인(테스트 기기에서만).

## 9. 만드는 사람에게 맡기는 것
- 네이티브 광고 카드의 세부 배치(디자인 `miaaz` 수치 안에서), 스켈레톤 애니메이션
- "저장 중" 화면의 정확한 시간(0.5~1초 안에서, 전면 준비 상태에 맞춰)
- 면제 판정에 필요한 "오늘 테스트함"·"오늘 100개 달성" 기록 방식(광고 상태 저장소에 날짜로 두는 등)
