# 스트릭(연속 운동 일수) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 듀오링고식 스트릭 — 홈의 연속 일수, 하루 첫 운동 뒤 축하 화면, 잃기 직전 알림, 스트릭 보호권 — 을 넣어 매일 앱에 돌아오게 한다.

**Architecture:** 스트릭은 저장하지 않고 "운동한 날짜 목록 + 오늘 날짜"에서 순수 함수로 계산한다(`src/domain/streak.ts`). 날짜 목록은 새 SQL 함수(RPC)로 받고, 저장에 실패해 폰에 보관 중인 운동의 날짜를 합친다. 알림 문구와 시각도 같은 입력에서 순수 함수로 계획하고 notifee 로 건다. RPC 가 없거나 실패하면 스트릭 UI·알림·축하를 모두 건너뛴다(fail-closed).

**Tech Stack:** React Native 0.79, TanStack Query v5, Supabase(RPC), AsyncStorage, `@notifee/react-native`, Jest.

**Spec:** `docs/superpowers/specs/2026-11-21-streak-design.md` — 화면 문구·스케치는 스펙 4·5장을 따른다.

**선행:** `docs/superpowers/plans/2026-11-21-daily-program.md` 가 먼저 끝나 있어야 한다 (같은 화면 파일을 고친다).

## Global Constraints

- 하루의 기준: 그날 푸쉬업 1개 이상 기록(모드 무관). 날짜는 `workout_date`(저장 시 기기 날짜, `formatKSTDate`)를 그대로 쓴다.
- 보호권: 스트릭이 7의 배수가 될 때 +1, 최대 2개, 안 한 날 자동 사용. 마일스톤: 3·7·14·30·50·100·200·365.
- 스트릭 정보가 없으면(RPC 미배포·실패·로딩) 스트릭 UI·축하·알림을 숨기거나 건너뛰고, 운동·네비게이션은 반드시 그대로 진행한다.
- 축하 화면은 결과 화면을 떠날 때만, 하루 한 번. 운동 중·휴식 중에는 띄우지 않는다.
- 알림은 로컬(notifee)만. 권한은 사용자가 켤 때만 요청한다. 기본값: 꺼짐, 저녁 21:00, 마지막 알림 22:30 고정.
- 테이블·컬럼을 추가하지 않는다. SQL 은 함수 1개(`STREAK.sql`)뿐이고 사용자가 수동 실행한다.
- 문구는 "사실 + 최고 기록 + 오늘 다시 시작". 꾸중 금지.
- 알려진 한계(수용): 보관했다가 나중에 보낸 운동은 일일 리더보드 집계(`add_daily_pushups`)에서 보낸 날의 개수로 더해진다.
- 테스트의 supabase 목은 `jest.mock('../../src/lib/supabase', factory)` 패턴을 쓴다.
- 검증 명령(모두 출력·실패 없이 끝나야 함): `npx jest __tests__/domain __tests__/remote __tests__/hooks __tests__/utils`, `npx tsc --noEmit -p tsconfig.json`, `npx eslint src __tests__`. `__tests__/App.test.tsx` 는 원래 깨져 있다.
- main 에 직접 커밋한다. 메시지는 한국어. push 하지 않는다.

  6. 비행기 모드에서 운동을 끝내면 "저장이 지연되고 있어요"가 보이고, 연결 후 앱을 다시 열면 기록과 스트릭에 반영된다 (히스토리에 중복 없음)
  7. 자정을 넘겨 앱으로 돌아오면 "오늘 아직"으로 바뀐다
