- 같은 색은 `primary` #7D5FFF 하나뿐이다(= `active-fill`).

## 7. 충돌과 열린 질문

### 7.1 최근 스펙과 충돌

1. **주 3일(18칸) vs 매일 7일** (가장 큼). Note 06 "6주 × 주 3일 = 18칸", 06 경로의 Day 1~3, 홈 "이번 주 3번 중 1번", 05 "내일은 쉬는 날이에요", "다음 운동 · 금요일", M-01 "6주 · 18번", SE-12 "주 3회로 정해지면 문구 교체 — 기획 대기". 그런데 `2026-11-21-daily-program-design.md`(승인됨, 이미 구현: c2d0307, 97ec244, a788fc6)는 주 7일 Day 1~7이다. 경로는 42칸 + 테스트 4개가 되고, "쉬는 날" 문구는 없어져야 한다. 디자이너가 7일 전환 전 기준으로 그렸다.
2. **주 단위 스트릭 vs 일 단위 스트릭**. 홈 "4주 연속 달성 중", 리더보드 "9주 연속", StreakDay의 'Rest(쉬는 날)'·'Planned' 변형, Note 03 "주 단위 스트릭". 스트릭 스펙(승인·구현됨: 7af515c, f0d7187)은 **일 단위 연속 일수**이고 1개 이상 하면 그날 인정이다. 디자이너도 "일/주 단위 스트릭 … 정해지면 그린다"고 보류했다. 결정이 필요하다.
3. **스트릭 보호권 규칙**. 스펙: 7일 이어갈 때마다 자동 +1, 최대 2, 빠진 날 자동 사용, 저장하지 않음(날짜에서 계산), "사용자가 직접 켜고 끄거나 사는 기능은 없다", "끊긴 스트릭 복구(유료/광고)"는 범위 밖. 디자인: 보상형 광고로 주 1회 획득, 최대 2장, "다음 날 아침에 쓸지 먼저 물어볼게요"(수동 사용), 광고 제거 구매 시 매달 2장, 06에서 '놓친 날 복구'. 계산 방식·저장 위치·자동/수동이 모두 다르다. SE-02 주석도 "보호권 월 2장 줄은 보상 기획 확정 전이라 숨김"이라고 미정을 인정한다.
4. **광고 배치 (spec 2026-10-09 §2)**. 스펙: 홈·히스토리·통계 **탭바 위 하단 고정 배너** + 운동 완료/챌린지 결과 떠날 때 전면. 디자인: 하단 고정 배너는 정책 위반이라 금지, 대신 홈·결과·리더보드 **네이티브**, 기록 **인라인 배너**, 결과 뒤 전면. 스펙의 "범위 밖"(리워드, 광고 제거 결제, ATT, 네이티브)을 디자인이 **전부 범위에 넣었다**. 다만 "운동 중·휴식·테스트 중 광고 없음"과 "설정·로그인·프로필 광고 없음"은 두 문서가 일치한다. ads plan(2026-10-19)은 화면 배치(Task 5)를 리디자인 뒤로 미뤄 뒀으므로 지금 새로 정하면 된다.
5. **전면 빈도**. 스펙 app_config 기본값: 하루 2회, 간격 180초, 유예 1회(첫 운동만 면제). 디자인: 하루 1회, 단위 상한 1회/12h(앱 전체 2회), **첫 3회 운동 면제**, 마일스톤 날·테스트 날('한 번에 몇 개?')·보상형 본 세션 면제. `domain/adFrequency.ts`는 유예·cap·gap만 안다. 면제 조건 3종이 추가로 필요하고 app_config 값을 바꿔야 한다. 또 디자인은 "테스트 날('한 번에 몇 개?')"라고 써서 챌린지 모드 전체를 테스트로 보는지, 프로그램 테스트만인지 애매하다.
6. **전면 타이밍과 스트릭 축하 화면 순서**. 스트릭 스펙 4.2와 ads plan: "축하 화면 → 광고". 디자인 흐름: 결과 [확인] → 저장 중 → 전면 → 홈. 축하 화면 자리가 없다(C-01~07 보류). 순서를 정해야 한다: 결과 → 저장 중 → 스트릭 축하 → 전면 → 홈?
7. **ATT**. 스펙: ATT 없이 `requestNonPersonalizedAdsOnly: true`, 첫 심사 변수를 늘리지 않음. 디자인: 첫 결과 뒤 ATT 사전 안내 + 시스템 창, 설정에 ATT 행. UMP: 스펙은 앱 시작 시 1회, 디자인은 "첫 실행은 카메라 권한만 → 첫 결과 뒤 ATT/UMP → 동의 후 SDK 초기화". SDK 초기화 시점이 달라진다(db5d65e의 SDK 연동 코드 확인 필요).
8. **로그인 강제 vs 로그인 전 사용**. 현재 앱은 로그인하지 않으면 AuthScreen만 보인다. 디자인 A-07은 "로그인 없이 측정 후 저장 요청"을 그리고, O-01 온보딩은 로그인 전에 뜨는지 뒤에 뜨는지 순서가 없다. 스트릭 스펙 6 "로그아웃하거나 다른 계정으로 로그인하면 남의 계정으로 보내지 않는다"와 비로그인 보관 → 로그인 후 업로드 규칙을 맞춰야 한다.
9. **100개 챌린지 UX 스펙과 결과·경로 화면**. 스펙: 하향은 권유(낮추기/한 번 더), 주차 직접 고르기는 1~6주차·레벨 1~3 어디든, 테스트 결과 화면 5가지 문구, 실패 우선 카드. 디자인 06은 "3주차 다시 하기 / 지금 다시 테스트" 두 버튼뿐이고 레벨이 보이지 않는다. 이 기능들을 경로 화면 어디에 둘지 정해야 한다. W-23 "모든 세트를 채워야 **다음 주차로** 넘어가요"는 스펙상 "다음 Day로"가 맞다.
10. **홈 '다른 운동'의 이름 변경**: '챌린지' → '한 번에 몇 개?', '세트' → '자유 세트'. 프로그램 테스트와 같은 측정이라고 O-04가 말한다. 결과 저장 방식(챌린지 = 최고 기록, 테스트 = 프로그램 반영)은 그대로 둘지 확인이 필요하다.

### 7.2 디자인 내부의 모호함·모순

- **밝은 화면 여부**: 디자인 시스템 헤더 "기록·통계만 밝은 화면" + `l-*` 토큰 vs Note 07 "앱 공통 어두운 토큰으로 바꿨다(밝은 화면은 눈부심)". 시안 07은 어둡다. **어두운 쪽이 최신으로 보인다.** `l-*` 토큰은 버려도 되는지 확인.
- **거치 거리**: 01 "얼굴에서 30~70cm, 화면이 천장을 보게 바닥에 평평하게" vs RS-04 팁 "폰을 바닥에 세워 1~1.5m 앞에 두기 · 얼굴과 어깨가 화면 가운데". 현재 앱 방식(얼굴 거리로 세기, 폰을 바닥에 눕힘)에 맞는 건 01이다.
- **리더보드 진입점 없음**(탭바 4개에 없고, 홈에도 없음).
- **설정 시안에 계정·이용약관·문의하기 행 없음**, 그런데 다른 상태가 이 행들을 전제한다.
- **"오늘 운동 완료" 홈 상태**(B3)는 CTA 라벨만 바뀌었다. 미리 하기·다음 Day 미리보기(daily spec 5.2) 표현이 없다.
- **보호권 사용 UX**("다음 날 아침에 쓸지 물어볼게요")를 그린 화면이 없다(보류된 ST 그룹).
- **M-03 다음 목표 시트**의 선택지가 그려져 있지 않다(무엇을 고르게 할지 기획이 필요).
- **버전 표기**: 시안 "1.4.0 · 새 버전 1.7.3"은 예시다. 실제 앱은 1.7.3.
- **lime 테마**가 변수에 남아 있다. 구현은 purple 하나로만 해도 되는지 확인(테마 전환을 기능으로 넣을 필요는 없어 보인다).
- **상태 칩 '인식됨'**(Design System) vs 시안 '얼굴 찾았어요'/'세는 중': 문구 통일이 필요하다.
- **결과 화면 [확인]의 행선지**: RS-01 "[확인] → 저장 중 → (전면) → 홈". 프로그램 결과에서 지금처럼 '프로그램으로' 가는 흐름이 사라진다(RS-14에만 [프로그램으로]).
- **"한 번에 몇 개?" W-12에 "3 / 5" 세트 표시**가 남아 있다(주석은 "세트 표시 없음"). 시안 복사 흔적으로 보인다.
