# 리디자인 1·2단계 설계 — 기반과 화면 리스킨

날짜: 2026-11-21 · 상태: 검토 중

## 1. 배경과 목표

디자이너가 앱 전체를 새로 그렸다(`pushon-redesign.pen`). 사용자는 이 디자인을 앱에 구현하길 원하고,
원칙을 이렇게 정했다: **보이는 모습은 디자인을 따르고, 기능·규칙은 지금 앱 기준을 지킨다.**
디자인은 주 3일 프로그램·주 단위 스트릭 시절에 그려져서, 이미 구현된 매일 운동(주 7일)·하루 단위 스트릭과
부딪히는 곳이 있다. 그런 곳은 지금 규칙으로 바꿔 그린다.

리디자인은 6단계로 나눴고(사용자 합의), 이 문서는 **1단계(기반)와 2단계(화면 리스킨)** 를 다룬다.
두 단계는 **한 번에 출시**한다 — 앱이 반쯤 바뀐 채로 나가지 않게.

| 단계 | 내용 | 이 문서 |
|---|---|---|
| 1 | 토큰·폰트·아이콘·공통 부품·탭바·어두운 내비게이션 | ✅ |
| 2 | 화면 리스킨 (홈, 운동, 결과, 100개 챌린지, 기록, 스트릭, 설정·계정·로그인, 자유 세트, 리더보드) | ✅ |
| 3 | 첫 실행 온보딩, 카메라 사전 안내, 코로 눌러서 세기, 소리·음성 | 다음 |
| 4 | 얼굴 인식 이벤트(네이티브) — 자동 3·2·1, 인식 끊김 화면 | 다음 |
| 5 | 광고 배치와 동의 (에드몹 계획 Task 5 재작성) | 다음 |
| 6 | 광고 제거 결제, 보상형 보호권, 리더보드 내 순위·순위 숨기기, 로그인 전 사용, 공유 카드 | 다음 |

### 성공 기준
- 모든 화면이 디자인의 어두운 테마·토큰·폰트·아이콘·부품으로 그려진다
- 지금 앱의 기능은 하나도 사라지지 않는다 (디자인에 없는 기능도 디자인 언어로 다시 입혀 남긴다)
- 매일 운동·하루 스트릭·통과/하향 규칙·저장 보관·축하 화면 등 기존 동작이 그대로다
- 화면에 "주 3일", "쉬는 날", "N주 연속" 같은 옛 규칙 표현이 없다

### 범위 밖 (이번에 안 함)
3~6단계 전부. 특히: 얼굴 인식 기반 자동 시작·끊김 화면, 소리·음성, 온보딩, 광고 화면 배치·동의,
광고 제거 결제, 보상형 보호권, 리더보드 새 RPC(고정 내 순위·참여자 수·부제), 순위 숨기기,
로그인 전 사용(A-07), 공유 카드 이미지, 밝은 화면(`l-*` 토큰), lime 테마, DB 스키마 변경.

### 이렇게 되면 실패 (anti-goals)
- 리스킨하면서 기존 로직(판정·저장·네비게이션 가드)을 다시 써서 동작이 바뀐다
- 디자인에 없다는 이유로 기능이 빠진다
- 디자인을 "비슷하게" 옮겨 수치(간격·크기·색)가 디자인과 다르다
- 운동 화면이 느려지거나 카운트가 밀린다 (330pt 숫자·배경 전환이 성능을 해치면 안 된다)

## 2. 원칙 A의 적용 규칙

1. **디자인에 있고 지금 규칙과 맞는 것** → 디자인 그대로.
2. **디자인에 있지만 옛 규칙 기준인 표현** → 지금 규칙으로 바꿔 그린다:
   - 주 3일 → 주 7일: 경로는 주차마다 7칸(총 42칸 + 테스트 깃발), "7 / 18칸" → "N / 42칸", Day 1~3 → Day 1~7
   - "내일은 쉬는 날이에요" → 삭제 (매일 운동). "다음 운동 · 금요일" → "다음 운동 · 내일"
   - 주 단위 스트릭("이번 주 3번 중 1번 · 4주 연속") → 하루 스트릭("N일 연속", 기존 `streakBanner` 문구)
   - "6주 · 18번" → 실제 통과 일수(`passedDayCount`)
   - "모든 세트를 채워야 다음 주차로" → "다음 Day 로" (100개 챌린지 UX 스펙)
3. **디자인에 없는 지금 기능** → 남기고, 디자인 부품·토큰으로 다시 입힌다 (§5에 목록).
4. **디자인에만 있는 새 동작 중 3~6단계 것** → 이번엔 숨긴다(버튼·행을 그리지 않는다).
   단, 운동 흐름의 새 동작 중 지금 기능과 부딪히지 않고 JS 만으로 되는 것은 이번에 넣는다(§4.3).

## 3. 접근 방식

| 방법 | 판단 |
|---|---|
| **A. 지금 화면을 그 자리에서 새 디자인으로 바꾼다 (채택)** | 토큰·부품 층을 먼저 만들고 화면을 하나씩 옮긴다. 기존 로직을 그대로 쓰고 겉만 바꾼다. main 에서 작업, 출시는 1·2단계가 모두 끝난 뒤 한 번 |
| B. 새 화면을 따로 만들어 스위치로 전환 | 같은 로직이 두 벌이 되어 고칠 때마다 양쪽을 손봐야 한다. 한 번에 출시하는 상황이라 얻는 게 적다 |
| C. 디자인의 HTML 내보내기를 자동 변환 | React Native 는 HTML 이 아니라 불가. HTML 은 정확한 수치를 읽는 참고 자료로만 쓴다 |

사용자는 결과를 정했고 만드는 방식은 맡겼다. A 는 작성자 판단.

  - [확인]의 목적지는 지금과 같다(프로그램 결과 → 100개 챌린지, 그 밖 → 홈). 100개 챌린지가 탭이 되므로
    결과 화면을 떠날 때 스택을 비우고 탭으로 간다: `StackActions.popTo('Tabs', {screen: 'Program', params: {notice}})`
    처럼 탭 화면에 파라미터로 안내 문구(notice)를 넘긴다. 축하(`celebrateThen`)는 지금처럼 떠나기 직전.
    지금 어느 결과 화면에도 전면 광고는 연결돼 있지 않다. "저장 중 → 전면 → 홈" 흐름은 5단계. (작성자 판단)
  - 100개 달성(08): 전체 화면 축하로 바꾼다. 사실 3줄은 지금 데이터(처음 테스트, 기간, 통과 일수, 총 개수).
    [공유 카드 만들기]는 6단계 전까지 숨김, [다음 목표 정하기]는 지금의 "다시 시작".

### 5.4 100개 챌린지 — `P0TkV`(06)
- 지킬 것: 진행 상태별 화면(로딩/오류/시작 전/진행/테스트 차례/오늘 완료/완료), 오늘 카드의 레벨·통과 조건·
  지난 실패 이유·하향 권유, 테스트 카드(기준·쉬고 재기), 레벨 다시 재기, 주차 직접 고르기, 그만두기,
  운동 알림 설정(§5.8 로 이동), 하향·주차 변경 안내(notice).
- 디자인: 경로 헤더(진행 칸, 처음→지난 테스트), 진행 막대, 주차별 PathNode 줄, 테스트 깃발, "힘들면 이렇게 골라도 돼요"
  [N주차 다시 하기] [지금 다시 테스트], 하단 고정 CTA.
- 바꿔 그릴 것:
  - 주차마다 **7칸**(Day 1~7), 테스트 주차 끝에 깃발. 디자인의 한 줄 3칸(76px 원)에는 7칸이 들어가지 않는다
    (같은 폭이면 36px 로 줄어 터치 최소 44 미만). → **주차 하나를 4칸 + 3칸 두 줄**로 그리고, 칸은 56px 원
    (터치 44 이상), 주차 라벨·상태 글자는 디자인 위치 그대로. 디자이너가 그리지 않은 변형이다. (작성자 판단)
  - 칸 세기: 칸은 6주 × 7일 = 42. 테스트는 칸이 아니라 깃발. 지난 칸 = (주차−1)×7 + (Day−1), 테스트 차례면
    (주차−1)×7 + 7. 20개 초과로 3주차부터 시작한 사람의 1·2주차 14칸은 "건너뜀"으로 흐리게 그리고 지난 칸에 넣는다.
    같은 주차를 반복해도 칸은 늘지 않는다(위치 기준). 이 계산은 `src/domain/` 순수 함수로 두고 테스트한다. (작성자 판단)
  - 헤더 "N / 42칸 지났어요".
  - 경로 맨 위에 오늘 카드(지금 내용)를 디자인 부품으로. 지난 실패·하향 권유·notice 는 여기.
  - [N주차 다시 하기] = 주차 직접 고르기로 그 주차 Day 1 (확인창 그대로), [지금 다시 테스트] = 레벨 다시 재기.
  - **전체 세트표(ProgramTable)** 는 디자인에 없지만 남긴다: 경로 화면의 "전체 세트 보기 · 주차 바꾸기" 링크 →
    디자인 언어로 다시 그린 표 화면(레벨 탭, Day 1~7 합계, 기준 범위, 내 기록, [여기서부터]).
  - 시작 전 화면(테스트 결과별 첫날 미리보기)과 100개 달성 후 화면도 같은 언어로.

## 6. 제약
- DB·서버 변경 없음. 모든 화면은 지금 데이터로 그린다.
- 네이티브 추가는 넷: 폰트 2종 번들, `lucide-react-native`, `@react-native-community/netinfo`, 화면 꺼짐 방지 라이브러리.
  다른 의존성 버전은 움직이지 않는다(`react-native-screens` 4.16.0 고정, `react-native-google-mobile-ads` 16.0.1 고정).
  설치할 버전은 RN 0.79.4·New Architecture 지원을 공식 문서로 확인한다.
- 기존 규칙의 **결과**(통과/실패·하향·스트릭·저장·보관·축하 판정)는 리스킨 때문에 바뀌면 안 된다.
  - 새 동작에 필요한 변경은 허용한다: 운동 상태 기계(`src/domain/workoutSession.ts`)에 단계·이벤트를 더하는 것
    (3·2·1 준비, 휴식 뒤 자동 다음 세트, 15초 더 쉬기, 일시정지·이어서, 백그라운드 멈춤). 기존 이벤트의 결과는 그대로이고,
    기존 테스트는 계속 통과해야 하며 새 단계는 테스트를 먼저 쓴다.
  - 화면이 필요한 데이터를 새로 계산해야 하면(지난번 대비, 월 요약, 경로 칸 등) 순수 함수로 `src/domain/` 에 추가하고 테스트한다.
  - 새 **읽기** 조회는 `src/remote/` 에 함수로 추가해도 된다(예: 같은 모드의 직전 운동). 기존 함수의 동작은 바꾸지 않는다.
- 화면 테스트 인프라가 없다. 검증: `npx jest __tests__/domain __tests__/remote __tests__/hooks __tests__/utils`,
  `npx tsc --noEmit -p tsconfig.json`, `npx eslint src __tests__`, iOS 빌드, 기기 확인.
- 기준 프레임 393×852. 다른 크기에서 넘치거나 잘리지 않게 한다(스크롤, 작은 기기 여백).
- 안드로이드도 같은 화면이 나와야 한다(폰트 이름·그림자·상태바 차이).
