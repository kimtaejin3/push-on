# 100개 챌린지 UX 개선 설계 (진행 규칙 · 안내 · 흐름 버그)

날짜: 2026-11-21 · 상태: 승인됨

## 1. 배경과 목표

100개 챌린지(6주 프로그램)를 실제로 써보면 세 가지가 걸린다.

1. **흐름이 끊긴다.** 100개를 달성해도 완료 화면이 안 나오고, 뒤로가기가 지난 결과 화면을
   다시 밟고, 저장이 실패해도 아무 말이 없다.
2. **못 채워도 넘어간다.** 하루 합계가 목표의 80%만 넘으면 자동으로 다음 날이 되고,
   80% 미만이어도 "완료하고 다음으로"가 주 버튼이다. 버거운 레벨을 낮춰주는 장치도 없다.
3. **이유를 알려주지 않는다.** 세트를 못 채웠을 때, 테스트 결과로 주차가 바뀌거나 반복될 때
   "왜 이렇게 됐는지 / 다음에 뭘 하면 되는지"가 화면에 없다.

목표는 **"앱이 내 상태를 정확히 판단하고, 그 이유를 그 자리에서 말해준다"** 는 느낌을 주는 것이다.

### 성공 기준
- 주차·Day·레벨이 바뀌거나 그대로 머무는 모든 경우에, 그 이유가 화면에 문장으로 보인다
- 세트를 하나라도 못 채우면 다음 Day 로 넘어가지 않는다
- 같은 Day 를 두 번 연속 못 채우면 레벨을 낮추라는 권유를 받는다
- 진행 중에 원하는 주차를 직접 골라 그 주차부터 다시 진행할 수 있다
- 100개를 달성하면 완료 화면을 본다
- 프로그램 화면에서 뒤로 가면 홈이 나온다
- 저장 실패가 조용히 지나가지 않는다

### 범위 밖 (이번에 안 함)
6주 전체 진척도 화면, 휴식 종료 소리·진동과 세트 자동 시작, 화면 꺼짐 방지, 운동 알림 개선,
용어 정리(챌린지/프로그램), DB 스키마 변경, 중단한 운동 이어하기.

### 이렇게 되면 실패 (anti-goals)
- 실패 안내가 꾸중이나 벌처럼 읽힌다 → 문장은 항상 "사실 + 이유 + 다음에 할 일"
- 사용자 동의 없이 레벨·주차가 내려간다 → 하향은 권유이고, 누르는 건 사용자
- 이유 없이 숫자만 바뀐다 → 상태 변화에는 반드시 설명이 따라온다

## 2. 접근 방식

갈리는 지점은 "연속 실패를 어디에 기록하나" 하나였다.

| 방법 | 장점 | 단점 |
|---|---|---|
| **A. 기존 `completed_days`(jsonb)에 모든 시도를 통과 여부와 함께 기록** (채택) | SQL 실행 불필요, 기기 간 동기화, 구버전 앱 호환, 프로그램 화면에서 "지난번 왜 실패했는지"를 계속 보여줄 수 있음 | 컬럼 이름과 달리 실패 기록도 들어감 |
| B. `pushup_programs` 에 실패 횟수 컬럼 추가 | 구조가 깔끔 | 배포 전 Supabase SQL 수동 실행 필요, 지난 실패 내용은 못 보여줌 |
| C. AsyncStorage 에 기록 | 가장 단순 | 재설치·기기 변경 시 사라짐 |

A 를 택한 이유: DB 작업 없이 배포할 수 있고, 시도 내용이 남아야 안내 문구를 만들 수 있다.
(작성자 판단. 사용자는 "두 번 연속 실패하면 낮추기"와 "이유를 제대로 안내"를 결정했고,
저장 방식은 맡겼다.)

## 3. 진행 규칙

### 3.1 통과 판정 (사용자 결정)
- **모든 세트가 목표 이상**이면 통과. 마지막 세트(가능한 만큼)는 최소치 이상이면 된다.
- 기존의 "합계 80%" 규칙(`dayAchievementRate`, `shouldSuggestRepeat`)과
  "완료하고 다음으로" 버튼은 없앤다.
- 참고: 마지막이 아닌 세트는 목표에 닿으면 자동으로 끝나므로, 실패는 사용자가 목표 전에
  "세트 종료"를 눌렀을 때만 생긴다.

### 3.2 통과 / 실패 후
- 통과 → 지금처럼 다음 Day (또는 테스트 차례).
- 실패 → 주차·Day·레벨 그대로. 다음 운동도 같은 Day.
- 운동을 끝까지 마쳤을 때만(마지막 세트 종료) 시도로 기록한다.
  중간에 "운동 그만두기"로 나간 것은 시도로 세지 않는다. (작성자 판단)

### 3.3 하향 권유 (사용자 결정: 두 번 연속 실패 시)
- **같은 주차·Day·레벨을 연속 2번 이상 실패**하면 하향을 권한다.
- 권유이지 강제가 아니다. 주 버튼은 "낮추기", 보조는 "이 레벨로 한 번 더". (작성자 판단)
- "이 레벨로 한 번 더"를 고르고 또 실패하면 다시 권한다 (3번째, 4번째도 마찬가지).
- 낮추는 대상:

| 현재 | 낮추면 |
|---|---|
| 레벨 2·3 | 같은 주차·같은 Day 의 한 레벨 아래 |
| 레벨 1, 2주차 이상 | 이전 주차 Day 1, 레벨 1 |
| 1주차 레벨 1 | 더 낮출 곳 없음 — 권유 없이 같은 Day 반복 |

  "레벨 1이면 이전 주차 레벨 1"인 이유: 표가 주차 묶음마다 열 기준이 달라서, 이전 주차의
  높은 레벨은 오히려 더 어렵다. 이전 주차 레벨 1만 확실히 쉬워진다. (작성자 판단)
- 낮추면 연속 실패 횟수는 처음부터 다시 센다. 이후 레벨은 기존처럼 주차 끝 테스트나
  "레벨 다시 재기"로 다시 올라갈 수 있다.
- "이 레벨로 한 번 더"는 기억하지 않는다. 통과하거나 낮출 때까지 권유는 프로그램 카드에
  계속 남고, 카드의 "이 레벨로 한 번 더"는 그대로 운동을 시작하는 버튼이다. (작성자 판단)

### 3.4 테스트로 인한 레벨 변화 (작성자 판단)
"동의 없이 내려가지 않는다"는 원칙은 **세트 실패로 인한 하향**에만 적용한다.
테스트(주차 끝 테스트, 최종 테스트, 레벨 다시 재기)는 사용자가 직접 잰 결과로 자리를
다시 정하는 것이므로 기존 규칙(`applyTest`, `retestLevel`)대로 레벨이 내려갈 수 있다.
대신 내려간 경우에도 결과 화면에서 반드시 설명한다 (4.6).

### 3.5 주차 직접 고르기 (사용자 결정)
진행 중인 사용자가 **본인 의지로 주차를 다시 골라 그 주차부터 다시 진행**할 수 있다.
오래 쉬어서 앞 주차로 돌아가고 싶을 때, 테스트를 잘못 재서 주차를 반복하게 됐을 때,
지금 주차가 너무 쉬울 때를 위한 장치다.

- 고르는 것: 주차(1~6)와 레벨(1~3). 시작은 항상 그 주차의 Day 1. (레벨·Day 는 작성자 판단)
- 앞 주차와 뒤 주차 모두 고를 수 있다. 막지 않되, 고른 주차·레벨의 기준이 최근 테스트
  기록보다 높으면 확인창에서 그 사실을 알려준다. (작성자 판단)
- 테스트 차례인 상태에서도 고를 수 있고, 고르면 테스트 차례는 풀린다.
- 고르면 연속 실패 횟수는 처음부터 다시 세고, "지난번 실패" 안내도 사라진다.
- 최근 테스트 기록(`lastTestReps`)과 운동 기록은 그대로 둔다.
- 진행 중인 프로그램이 있을 때만 가능하다. 시작 전·완료 상태에서는 지금처럼 초기 테스트로 시작한다.

### 3.6 기록 형태
`completed_days` 배열에 시도마다 하나씩 덧붙인다.

```
{ week, day, level, targets: number[], reps: number[], passed: boolean, completed_at }
```

- `passed` 가 없는 예전 기록은 통과로 본다.
- 연속 실패 횟수 = 배열 끝에서부터, 현재 (주차, Day, 레벨)과 같고 `passed === false` 인
  기록이 이어지는 개수.
- 구버전 앱은 이 배열을 읽지 않고 덧붙이기만 하므로 영향이 없다.
- 주차를 직접 고르면(3.5) 그 사실을 표시하는 기록을 하나 덧붙여 연속 실패가 거기서 끊기게
  한다. 이 표시는 시도가 아니므로 "통과한 운동 일수" 같은 집계에 넣지 않는다.
  표시의 구체적 형태는 만드는 사람이 정한다.

## 4. 안내 화면

문구는 예시다. 말투와 정확한 표현은 만드는 사람이 기존 화면 톤에 맞춰 다듬되,
**들어가야 하는 정보**는 아래 그대로여야 한다. 예시 숫자는 2주차 Day 2 (레벨 3: 14·16·12·12·17+,
레벨 2: 10·12·9·9·13+, 휴식 90초).

### 4.1 프로그램 화면 — 오늘 카드
레벨과 통과 조건을 항상 보여준다.

```
2주차 · Day 2 · 레벨 3
14 · 16 · 12 · 12 · 17+
세트 사이 휴식 90초 · 마지막 세트는 가능한 만큼
모든 세트를 채우면 Day 3로 넘어가요
[ 오늘 운동 시작 ]
```

지난 시도가 실패였으면 카드 위에 이유를 남긴다 (다음에 통과할 때까지 유지).

```
지난번(11월 19일)에 세트 2·4를 못 채워서 Day 2를 다시 해요
  세트 2  13 / 16   세트 4  10 / 12
```

연속 2번 이상 실패 상태면 같은 자리에서 하향을 권한다.

```
Day 2를 두 번 연속 못 채웠어요. 레벨 3이 지금은 조금 버거울 수 있어요.
레벨 2로 낮추면 오늘 세트는 10 · 12 · 9 · 9 · 13+ 예요
[ 레벨 2로 낮추기 ]    이 레벨로 한 번 더
```

낮춘 직후에는 무엇이 바뀌었는지 한 번 알려준다 ("레벨 3 → 2로 낮췄어요. 오늘 세트가 바뀌었어요").

### 4.2 운동 중
- 카운트 아래에 목표까지 남은 개수를 보여준다 ("목표까지 3개"). 마지막 세트는 최소치를
  넘기면 "최소 달성, 가능한 만큼 더"로 바뀐다.
- 확인창은 띄우지 않는다 (폰이 바닥에 있어서 누르기 어렵다).

### 4.3 휴식 화면 — 세트 직후 즉시 안내
지금은 휴식 중에도 방금 끝낸 세트의 번호·목표가 그대로 보인다. 이렇게 바꾼다.

```
세트 2 · 13 / 16   3개 부족
오늘은 모든 세트를 채워야 Day 3로 넘어가요.
이번엔 Day 2를 다시 하게 되지만, 남은 세트도 끝까지 하면 다음 도전이 쉬워져요.

휴식  90
다음: 세트 3 · 목표 12회
[ 건너뛰기 ]
```

- 채웠으면: `세트 2 · 16 / 16 완료` + 다음 세트 정보만.
- "다시 하게 된다"는 설명은 그 운동에서 처음 못 채운 세트 직후에만 길게, 이후에는
  부족 개수만 짧게 보여준다.
- 세트 모드(프로그램 아님)에서는 결과와 다음 세트 정보만 보여주고 통과/실패 문구는 없다.

### 4.4 운동 요약
맨 위에 판정, 그다음 세트별 결과(부족한 세트 표시), 마지막에 다음에 할 일.

통과:
```
2주차 Day 2 통과
모든 세트를 채웠어요
세트 1  14 / 14     세트 2  16 / 16   ...   세트 5  19 / 17+
다음은 2주차 Day 3 · 하루 쉬고 하는 걸 권해요
[ 프로그램으로 ]
```
(주차 마지막 날이면 "다음은 테스트예요", 테스트 없는 주차면 "다음은 3주차 Day 1")

실패 1번째:
```
2주차 Day 2 · 한 번 더
세트 2·4가 목표에 못 미쳤어요
세트 1  14 / 14
세트 2  13 / 16   −3
세트 3  12 / 12
세트 4  10 / 12   −2
세트 5  17 / 17+
모든 세트를 채워야 Day 3로 넘어가요. 다음 운동도 Day 2예요.
한 번 더 못 채우면 레벨을 낮추는 걸 권할게요.
[ 프로그램으로 ]
```

실패 연속 2번째 이상:
```
2주차 Day 2 · 두 번 연속 못 채웠어요
(세트별 결과 동일)
레벨 3이 지금은 조금 버거울 수 있어요.
레벨 2로 낮추면 Day 2는 10 · 12 · 9 · 9 · 13+ 예요.
[ 레벨 2로 낮추기 ]    이 레벨로 한 번 더
```
(레벨 1·2주차 이상이면 "이전 주차로 돌아가기", 1주차 레벨 1이면 권유 없이
"가장 쉬운 단계예요. 같은 Day를 다시 해요")

### 4.5 테스트 카드 (프로그램 화면)
통과 기준과 쉬고 재라는 권고를 보여준다.

```
2주차 테스트
16개 이상이면 3주차로 넘어가요. 16개 미만이면 2주차를 한 번 더 해요.
충분히 쉰 날에 재는 걸 권해요. (오늘 Day 3를 했다면 내일 이후에)
[ 최대 횟수 테스트 ]
```
- 기준: 2주차 끝 16개, 4주차 끝 31개, 5주차 끝 46개, 최종 100개.
- 쉬라는 것은 권고만 하고 막지는 않는다. 마지막 운동이 오늘이면 괄호 문구를 강조한다. (작성자 판단)

### 4.6 테스트 결과 화면
"훌륭해요! 세트를 완료했습니다" 대신, 결과가 무엇을 뜻하는지 말한다.

| 상황 | 안내 |
|---|---|
| 초기 테스트 | "8개 · 1주차 레벨 2로 시작해요" + 첫날 세트 |
| 다음 주차로 | "23개 · 3주차 레벨 2로 넘어가요" |
| 기준 미달 | "14개 · 3주차 기준(16개)에 2개 부족해요. 2주차를 한 번 더 하고 다시 재요" |
| 최종 미달 | "87개 · 100개까지 13개 남았어요. 6주차를 한 번 더 해요" |
| 최종 통과 | 완료 화면(5.1)으로 |
| 레벨 다시 재기 | "15개 · 이번 주 레벨이 2 → 3으로 바뀌어요" 또는 "레벨은 그대로 2예요" |

주차를 반복하거나 레벨을 다시 잴 때 레벨이 **내려가면** 그 사실과 이유를 같이 말한다.
예: "8개 · 2주차를 한 번 더 해요. 이번 결과에 맞춰 레벨도 3 → 2로 조정했어요",
"17개 · 이번 주 레벨이 3 → 1로 내려가요. 지금 기록에 맞는 세트로 바뀌어요".

### 4.7 주차 바꾸기
기존 "전체 프로그램" 화면(레벨 탭 + 주차별 세트 표)을 그대로 쓴다. 표를 보면서 고르는 게
가장 판단하기 쉽기 때문이다. (작성자 판단)

- 프로그램 화면의 진입 링크를 "전체 세트 보기 · 주차 바꾸기"로 바꾸고, 테스트 차례 카드에도 둔다.
- 진행 중인 프로그램이 있으면 주차 카드마다 "여기서부터" 버튼이 보인다.
  지금 위치의 카드에는 "지금 여기 · Day 2"를 표시한다.

```
전체 프로그램
[ 레벨 1 ] [ 레벨 2 ] [ 레벨 3 ]

3주차   지금 여기 · Day 2
  Day 1  12 · 17 · 13 · 13 · 17+
  ...
4주차                         [ 여기서부터 ]
  Day 1  18 · 22 · 16 · 16 · 25+
  ...
```

누르면 확인창:

```
4주차 · 레벨 2 · Day 1부터 다시 진행할까요?
지금 위치(3주차 Day 2 · 레벨 2)는 사라져요. 운동 기록은 그대로 남아요.
4주차 레벨 2는 최대 21~25개를 기준으로 한 세트예요. 최근 테스트는 18개였어요.
[ 취소 ]  [ 이 주차로 ]
```

- 세 번째 줄은 고른 주차·레벨의 기준이 최근 테스트 기록보다 높을 때만 보여준다.
  기준 범위 — 1·2주차: 5개 이하 / 6~10 / 11~20, 3·4주차: 16~20 / 21~25 / 26 이상,
  5주차: 31~35 / 36~40 / 41 이상, 6주차: 46~50 / 51~60 / 61 이상.
- 바꾼 뒤 프로그램 화면으로 돌아와 한 번 알려준다 ("4주차 · 레벨 2 · Day 1부터 다시 진행해요").

## 5. 흐름 버그 수정

### 5.1 100개 달성 화면
- 원인: 완료하면 상태가 `completed` 가 되는데 조회는 `active` 만 가져와서, 달성 직후
  소개 화면이 뜬다.
- 바꿀 동작: **가장 최근에 만든 프로그램 하나**를 기준으로 한다. 그것이 active 면 진행 화면,
  completed 면 완료 화면, abandoned 면 프로그램이 없는 것(소개 화면)으로 본다.
  완료 상태면 완료 화면이 **다시 시작하기 전까지 계속** 보인다. 홈 카드 상태는 "완료".
  (완료 후 다시 시작했다가 그만둔 사람에게 옛 완료 화면이 되살아나지 않게 하기 위함. 작성자 판단)
- 출시 시점에 이미 completed 기록이 최신인 기존 사용자는 그때 완료 화면을 처음 보게 된다 (의도된 동작).
- 완료 화면: 최종 테스트 횟수, 시작일부터 걸린 기간, 통과한 운동 일수. "다시 시작"은
  확인을 거쳐 초기 테스트로 가고, 새 프로그램은 그 테스트 결과로 만든다.
  완료된 기록은 `completed` 로 남긴다 (지금처럼 `abandoned` 로 바꾸지 않는다).

### 5.2 뒤로가기
- 원인: React Navigation 7 의 `navigate('Program')` 이 기존 화면으로 돌아가지 않고 새로 쌓는다.
- 바꿀 동작: 운동 요약·테스트 결과에서 프로그램으로 갈 때 기존 프로그램 화면으로 돌아간다.
  프로그램 화면에서 뒤로 → 홈. 지난 요약/결과 화면으로는 돌아갈 수 없다.
- 운동 중(카운팅·휴식) 안드로이드 뒤로가기 버튼이나 iOS 스와이프로 나가려 하면
  "운동 그만두기" 확인창을 거친다. 나가면 카운팅 세션을 멈춘다.
- "운동 그만두기" 확인창 문구에, 프로그램 운동이면 "오늘 운동은 처음부터 다시 해야 해요"를 넣는다.

### 5.3 조용한 실패와 로딩
- 프로그램 조회 중에는 로딩 표시. 조회가 **실패**하면 소개 화면이 아니라 오류와 "다시 시도".
  홈 카드도 조회 전·실패 시에는 "시작 전"을 보여주지 않는다.
- 새 프로그램은 조회가 성공했고 진행 중인 프로그램이 없을 때만 만든다 (중복 생성 방지).
- 테스트 결과·운동 결과를 프로그램에 반영하는 저장이 실패하면 화면에 알리고 "다시 시도"를
  준다. 통과했는데 Day 가 그대로이거나, 테스트를 했는데 결과가 사라지는 일이 조용히
  일어나면 안 된다.
- 첫 테스트 직후 프로그램이 만들어지는 동안 소개 화면이 다시 보이지 않게 한다.

## 6. 제약
- React Native + Supabase. DB 스키마는 건드리지 않는다 (SQL 수동 실행 없음).
- 구버전 앱이 같은 DB 를 쓴다. 구버전은 `status = 'active'` 한 건만 읽고
  `completed_days` 에 덧붙이기만 한다.
- 진행 규칙은 `src/domain/hundredPushups.ts` 의 순수 함수로 두고 `__tests__/domain` 에서
  검증한다. (`__tests__/App.test.tsx` 는 원래 깨져 있음 — 이번 작업과 무관)
- 세트 모드(`source.kind === 'sets'`)의 동작은 4.3에 적은 휴식 화면 표시 외에는 바꾸지 않는다.
